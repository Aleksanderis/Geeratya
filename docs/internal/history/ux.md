# UX history

Per-issue "implemented by" notes and the render gap table moved word for word out of `ux-look.md`. Not required reading; the area docs describe current behaviour.

## Overlay box (ux-look.md, section 7)

**As implemented by #525.** One `OverlayBox` (rounded accent frame, title as the filled accent chip, `Backdrop` for the dimmed view, `Over` to splice the box into the view rows, `Cover` for the mouse box) draws the field form, comment editor, suggestion rows, palette, help, confirm, jump, source picker, context menu and profile form, and the which-key popup (frame and chip only: it keeps the view undimmed and flush right, as no Backdrop is specified for it). The view is `SpanGround.Dim` (24-bit: text blended towards `Theme.ScrimBackground` by `Theme.DimAmount`; 16 colours: faint, or bright black when the glyph set is ASCII, which marks a classic console; no colour: unchanged), the box is `SpanGround.Surface` (24-bit: `Theme.Surface`, the page colour unless the theme sets `overlayBackground`; the view is `Theme.ScrimBackground`; other tiers keep the default background); a box under another overlay is both. Confirm frames use `bad` for requests marked `Destructive` (delete issue, delete comment, remove profile), `warn` otherwise and the accent for notices. A click on the body outside the reported box is the Backdrop. **As implemented by #562.** Boxes no longer sit at their full width: the form is up to 90 columns (more for a long label or title), the source picker up to 76 and the comment editor up to 80, the form's decided from its labels and title, the others constant, and never from what is typed, so a box does not change width while the user types (only the confirm shrinks, to its longest line, at least 30 and at most 62 columns). Help, form, palette, source picker and jump show `▲`/`▼` (ASCII `^`/`v`) in the right padding column when rows are hidden above or below; the profile form footer is hint chips; the wheel over the rows of the source picker and the jump prompt moves the highlight 3 rows like the palette. The profile list overlay is gone (#535), so its 18-row cap and footer chips no longer apply. Deviations kept on purpose: the palette keeps the height of its unfiltered list (up to 18 rows) while filtering; the form and the comment editor stay anchored one row below the top of the body (their height changes while suggestions open, so centring would move the field being typed in); the source picker and jump prompt are capped at 18 rows; footers of the form, editor, palette, picker, jump and profile form are hint chips (key bold accent, label muted, `OverlayBox.Hints`); confirm frames use `bad` for requests marked `Destructive` (deletes, removing a profile, side-effecting transitions, completing a sprint, moving several issues to a sprint) and the chip names the action and target (`Move GCM-8`; `ConfirmRequest.Heading`).

## Profile manager and form (ux-look.md, section 7)

**As implemented by #528.** The manager is the profile list overlay (the existing popup component) with two buttons, Add and Edit, and its keys are `Enter` switch, `Ctrl-a` add, `Ctrl-e` edit, `Ctrl-x` remove, `Esc` close. The form shows the four fields at once (Name, Site URL, Account, Token) with the focused row in the selection role, a note line (validation as you type, or the connection test result), the buttons `Test connection`, `Save`, `Cancel` and the keys `Tab` field, `Ctrl-s` save, `Alt-t` test (`Ctrl-t` is the picker's open-in-new-tab key), `Esc` cancel. The token source row is not shown: the token is stored in the OS secret store, and `GEERATYA_TOKEN` serves only a single profile without a store (`ux.md`, "Profiles"), so there is nothing per profile to choose. **As implemented by #535.** The manager is a full-body screen (`ProfileManagerScreen`, one `FrameGrid` with a list pane of 40% of the width, 26 to 44 columns, and a details pane; under 60 columns the details pane is left out). The details are Name, Site, Account, Token (the source only, looked up by the host through `LoadTokenSourcesEffect`; `looking up...` until it answers) and Status (the connection line for the active profile, `not checked` for others, so no request goes to an inactive site). The tab row shows one `Profiles` chip (no jump chip: it is not a tab of a site), the status line shows the notice or the active profile's connection, and the Add and Edit buttons sit in the last row of the list pane. The form and the remove question draw over it (dimmed) and return to it. The active mark is `●` (`*` in the ASCII tier). With no profile the same screen is shown at start with an empty list.
